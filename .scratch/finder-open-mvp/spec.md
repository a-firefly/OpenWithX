# OpenWithX MVP 规格

状态：需求决策已确认。2026-10-22 用户接受 Q29，取消项目父目录配置，以本规格中的自动覆盖规则替代先前的目录配置和相关授权约定。系统可行性与公开发布条件尚待验证；当前已完成 issue 01 首轮验证原型与工程配置，尚未编写正式业务实现；Debug 构建和自动测试通过，但 26.7 实机打开与跨进程应用授权失败，技术关卡未通过。详见 [验证报告](validation/issue-01/report.md)。

## 最新覆盖决策

安装并手动启用扩展后，无需选择任何项目父目录，由应用自动覆盖内置磁盘和已挂载本地外接磁盘上的普通文件夹。保留单选与特殊对象排除规则，云盘、网络卷和特殊虚拟位置暂不承诺支持；“无需目录配置”不代表读取全盘的授权或所有 Finder 位置无条件可用。

## 产品目标与平台

面向已安装正式版 Visual Studio Code、会使用 Finder 的普通开发者，让用户在 Finder 中右击单个项目文件夹，通过一级菜单直接交给 VS Code 打开。首次配置和日常使用均无需终端命令。

- 支持 macOS 26 系列，从 26.0 起，仅 Apple Silicon。
- 简体中文菜单为“使用 VS Code 打开”，英文为“Open in VS Code”。界面跟随系统语言，其他语言回退英文；不提供应用内语言切换。
- 首个公开版本通过官网或 GitHub 直接下载，交付 Developer ID 签名、Apple 公证的 Apple Silicon DMG，引导安装到“应用程序”。后续手动下载更新，不自动检查更新，不要求 Mac App Store 上架。
- 开发者账号、证书和发布条件在发布阶段检查。本机开发构建不等于完成公开发布交付。

## 首次配置与主应用

1. 打开 OpenWithX，自动发现正式版 VS Code。允许重新检测或手动选择一个正式版副本；未发现时提供官方下载入口，不自动安装。
2. 应用自动准备本地磁盘的 Finder 菜单覆盖范围，不提供项目父目录配置步骤。
3. 引导用户到系统设置手动启用 Finder 扩展。主界面展示 VS Code、扩展启用状态和支持范围说明。
4. 引导用户手动在 Finder 中右击本地普通文件夹，完成一次实际打开验证。未实际验证时不显示“菜单已验证可用”；系统扩展启用状态与用户端到端验证分别呈现，不自动操作 Finder。
5. 配置完成后用户可以退出主应用。日常通过 Finder 操作，不要求主应用常驻 Dock 或菜单栏；后台组件生命周期由集成机制决定。

主应用为配置和故障排查入口。正常打开成功时不启动配置界面；主应用已退出而打开失败时，允许自动启动或激活它，集中展示错误与恢复操作。

## Finder 范围与菜单规则

- 自动覆盖内置磁盘与已挂载本地外接磁盘上的普通文件夹，无需用户选择项目父目录；覆盖应随本地外接磁盘挂载与卸载更新。
- 例如 `~/Developer` 与其中的 `ProjectA` 都是普通文件夹时，右击其中任意一个均属于目标体验，不再有仅支持所选父目录子文件夹的限制。
- 网络共享、云盘目录、未下载到本地的项目和特殊虚拟位置暂不承诺支持。
- 仅单选普通文件夹时显示菜单。文件、多选项目、应用包（如 `.app`）、Finder 替身和符号链接均隐藏菜单，不自动解析链接。普通文件夹名称包含中文或空格应正常支持。
- 文件夹窗口空白处打开当前目录不在 MVP 范围内。
- 扩展已启用且目标为支持的普通文件夹时，未发现 VS Code 仍显示菜单；点击后打开主应用，引导重新检测、选择应用或主动访问官方下载页面。
- 一级菜单是核心要求；仅提供“服务”或“快速操作”子菜单不满足要求。具体显示与覆盖能力仍需目标系统实测。

## VS Code 发现与打开行为

- 仅支持正式版 VS Code。使用原生 `NSWorkspace` 发现应用并将目标文件夹 URL 交给指定应用，不依赖 `code` 命令、PATH、终端或 shell 脚本。
- 未手动指定时，采用系统发现的正式版副本，不额外保证多副本之间的固定自动排序。用户可以手动固定某一正式版副本。
- 手动指定的副本被移动、删除或变得不可用时，提示重新选择，不静默切换其他副本。
- 打开时激活 VS Code。窗口复用或新建遵循 VS Code 自身设置，不强制新建应用进程或窗口，不提供窗口策略设置。
- 同一目标文件夹的打开请求尚未返回时合并重复点击，返回后再次点击视为新请求；不同目标分别处理。不保证阻止请求完成后 VS Code 再次打开同一项目。
- 成功标准为系统成功接受交给 VS Code 的打开请求，成功时不弹提示。该标准不代表编辑器已完成加载；VS Code 工作区信任提示和内部加载错误由 VS Code 处理。

## 配置、权限与隐私

- 在本机保存 VS Code 选择及必要的应用授权，不保存项目父目录列表或依赖其授权；菜单范围由应用自动维护并在重启后恢复。
- 外接磁盘断开后不再作为当前可用目标，重新挂载后自动恢复其普通文件夹的覆盖，无需用户再次配置目录。
- 不读取项目文件内容、不修改项目，不要求管理员、辅助功能或完全磁盘访问权限。最小权限与沙盒优先的约定继续保留。
- 正常首次配置不要求选择任何目录（包括选择磁盘根目录）来获得授权。所选目标 URL 在沙盒中的识别与原生打开权限仍需验证；若必须新增目录授权流程才能实现，应重新讨论，不能静默恢复已取消的目录配置步骤。
- 主应用和 Finder Sync 扩展优先保持沙盒。监控目录与访问授权分别处理，路径字符串或监控范围本身不代表授权。
- 不保存打开历史，不收集使用统计，不自动上传诊断信息，不自动检查更新。允许用户主动打开官方下载网页。
- 必要诊断仅保留在本机，默认避免记录完整项目路径；错误界面可展开原始错误细节。

## 错误与恢复

发生可识别的打开失败时显示一次明确提示，默认解释用户可理解的原因并提供相应恢复操作。原因未知时如实说明；不自动循环重试，也不默认要求重启 Finder。无需通知权限。

| 场景 | 预期反馈与恢复 |
| --- | --- |
| 未发现 VS Code | 主应用提供重新检测、手动选择和官方下载入口 |
| 手动指定副本失效 | 提示重新选择，不切换到另一副本 |
| 目标被移动或删除、磁盘在点击前后断开 | 如系统或必要检查能识别，明确提示目标不可用，引导检查目录或磁盘 |
| 必要访问被拒绝 | 明确提示并按实际错误提供检查权限或排障入口；不默认要求选父目录或授予全盘访问 |
| 系统拒绝启动或打开请求 | 展示可识别的原因和恢复入口；原始错误可展开 |
| 未知失败 | 如实提示失败，提供主应用中的配置与排障入口 |
| 系统已接受请求后，VS Code 内部报错 | 不伪装为 OpenWithX 可检测的失败，由 VS Code 处理 |

## 集成决策与技术验证关卡

首选 Finder Sync 扩展，由应用自动登记本地磁盘覆盖范围，实现普通文件夹一级菜单。可参考自动登记已挂载卷并响应挂载变化的开源实现，但具体登记方式需实测确定。Apple 将 Finder Sync 定位于文件同步应用，并非通用 Finder UI 修改机制；因此以下为必须验证的条件，不是已验证能力：

1. macOS 26 系列 Apple Silicon 上，无目录配置时本地单个普通文件夹的一级菜单与正确目标 URL。
2. 内置磁盘、本地外接磁盘、嵌套子目录的自动覆盖；挂载、卸载与重新挂载的范围更新；非支持输入隐藏菜单。
3. 主应用退出、扩展冷启动、系统重启后的自动范围恢复、应用配置读取和原生打开链路。
4. 保持最小权限与沙盒、不预先授权父目录时，能否正确识别所选对象类型并原生打开；VS Code 手动选择授权的保存、跨进程使用与失效恢复。
5. 失败时启动或激活主应用，传递错误并显示可操作的提示；不依赖扩展直接弹出对话框的未经验证行为。
6. 扩展启用状态的可靠检测、目标系统设置引导与实际菜单验证的区分。
7. 桌面、文稿等受保护位置，以及与其他 Finder Sync 扩展共存时的菜单表现和打开失败处理；特殊虚拟视图、侧边栏、云盘等不因自动登记磁盘而视为已验证支持。

若不能满足核心要求，带实测证据重新讨论；不静默增加权限、恢复父目录配置、关闭沙盒或降级为子菜单。本次需求澄清不授权立即编写验证或业务代码。

## 验收清单

以下条目从已确认需求推导，尚未执行验收：

| 范围 | 验收场景 |
| --- | --- |
| 平台 | macOS 26.0 起的 Apple Silicon 目标系统构建与运行；当前工程 `26.7` 需在实施时调整并验证 |
| 首次配置 | 无终端、无目录选择，完成应用发现、扩展启用引导和手动 Finder 验证 |
| 核心打开 | 自动覆盖的本地单个普通文件夹显示一级菜单，点击后交给正确 VS Code 并激活 |
| 路径 | 中文、空格及嵌套子目录正确打开；不会因路径被当作命令文本而改变语义 |
| 非支持输入 | 文件、多选、应用包、Finder 替身、符号链接不显示菜单；空白处无本功能入口 |
| 外接磁盘 | 挂载时自动覆盖；断开时更新范围，发生打开失败时有反馈；重新挂载无需配置 |
| 自动覆盖 | 不同本地路径与嵌套目录均无需父目录白名单；范围随本地磁盘状态更新 |
| 应用发现 | 自动发现、未安装、多副本手动指定及指定副本失效符合规则 |
| 生命周期 | 主应用退出、扩展冷启动和系统重启后，范围自动恢复并可打开 |
| 权限与共存 | 无父目录授权流程即可完成核心打开；访问被拒绝时反馈明确；验证其他扩展共存，无额外高权限要求 |
| 打开语义 | 遵循 VS Code 窗口设置；成功无提示；不将加载完成作为成功标准 |
| 重复点击 | 在途同目标请求合并；返回后的请求与不同目标分别处理 |
| 错误界面 | 主应用关闭时失败能启动或激活它；提示一次、原因明确、恢复可操作 |
| 状态真实性 | 已启用不等于已验证，未端到端验证时不声称菜单已验证可用 |
| 本地化与隐私 | 中英文及其他语言回退符合约定；无历史、遥测、自动上传或更新检查 |
| 公开交付 | 签名与公证的 Apple Silicon DMG，在干净目标环境验证安装、扩展启用和打开流程 |

业务逻辑实施遵循项目 TDD 约定：先失败测试，再实现与重构；系统集成还需目标 macOS 环境的手动端到端验证。此阶段不编写或运行业务测试。

## 明确不在 MVP 范围内

Cursor、Qoder、VS Code Insiders、自定义任意开发工具；项目父目录配置与白名单管理；多选、文件、空白处打开当前目录；所有 Finder 位置无例外的覆盖保证，含网络卷、云盘及特殊虚拟位置；链接解析；强制窗口策略；编辑器加载监控；常驻状态栏功能；打开历史、遥测和自动更新；旧版 macOS、Intel 与 Mac App Store 上架。
