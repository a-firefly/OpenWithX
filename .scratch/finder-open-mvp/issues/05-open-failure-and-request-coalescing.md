# 05: 打开失败可恢复，重复点击行为明确

**What to build:** Finder 打开失败时，启动或激活主应用并集中展示一次明确、可操作的错误提示。同一目标文件夹的在途打开请求合并，不同目标分别处理。

**Blocked by:** 02 — 从 Finder 打开本地目标文件夹。

**Status:** ready-for-agent

- [ ] 同一目标的请求尚未返回时合并重复点击，返回后再次点击作为新请求；不同目标分别处理，不承诺阻止请求完成后的重复打开。
- [ ] 主应用已退出时，失败能启动或激活它并传递错误；不依赖扩展直接弹出对话框，不要求通知权限。
- [ ] 对可识别的 VS Code 缺失或指定副本失效、目标移动或删除、磁盘断开、访问拒绝及系统拒绝启动或打开提供相应原因与恢复入口；未知错误如实说明。
- [ ] 每次失败打开请求只展示一次明确提示，原始错误可展开；不自动循环重试，不默认要求重启 Finder 或授予完全磁盘访问权限。
- [ ] 恢复操作可引导重新检测、重新选择 VS Code、主动访问官方下载页面，或检查目标、磁盘和实际权限问题；指定副本失效规则不允许静默回退。
- [ ] 系统接受请求后 VS Code 内部加载或工作区信任问题不伪装为 OpenWithX 可检测的失败；成功保持无提示。
- [ ] 必要诊断仅保存在本机，默认避免完整项目路径，不保存打开历史、不自动上传诊断。
- [ ] 按 TDD 验证请求合并、错误映射与提示去重，并实测主应用退出后的失败唤起和恢复。与任务 04 的真实选择流程最终联验由任务 06 完成；变化同步相关文档。
