# 01: 验证无目录配置的 Finder 集成与沙盒打开链路

**What to build:** 用最小端到端验证确认：macOS 26 系列 Apple Silicon 上，用户无需选择目录或额外高权限，即可在 Finder 单选本地普通目标文件夹，通过一级菜单交给正式版 VS Code 打开。交付可复现的实测证据和明确的通过或失败结论，为后续实现确定路线。

**Blocked by:** None (can start immediately).

**Status:** ready-for-human

- [ ] 验证主应用与 Finder Sync 扩展保持沙盒；不预先授权父目录或磁盘根目录，不依赖管理员、辅助功能、完全磁盘访问权限、终端或 shell。
- [x] 在目标 macOS 26 Apple Silicon 环境验证一级菜单、正确目标 URL 及原生 NSWorkspace 打开；记录系统版本、构建配置、权限状态、操作步骤、预期与实际结果。按 2026-10-22 用户追加决定，26.7 通过可代表最低 26.0 的版本关卡；仍须记录 26.0 未实测，不将验收豁免写成实测证据。
- [ ] 验证内置磁盘不同位置及嵌套普通文件夹、中文与空格路径；验证本地外接磁盘挂载、卸载与重新挂载后的自动覆盖，无需目录配置。
- [ ] 验证文件、多选、应用包、Finder 替身、符号链接均隐藏菜单，窗口空白处无本功能入口；记录沙盒中识别对象类型的可行方法。
- [ ] 验证主应用退出、扩展冷启动、系统重启后的覆盖恢复、配置读取和打开请求；成功时不启动配置界面。
- [ ] 验证手动选择正式版 VS Code 后，必要授权的持久保存、跨进程使用及副本失效恢复；监控范围和路径字符串不得作为访问授权的证明。
- [ ] 验证失败时能启动或激活主应用并传递错误；不依赖扩展直接弹出对话框的未经验证行为。
- [ ] 验证扩展启用状态的可靠检测及目标系统设置引导，区分系统启用状态与用户实际菜单验证。
- [x] 验证桌面、文稿、下载位置中的文件夹能在 VS Code 新窗口正确打开（用户人工确认）。
- [ ] 验证与其他 Finder Sync 扩展共存时的菜单表现和失败处理；记录限制，不将云盘、网络卷或特殊虚拟位置视为已验证支持。
- [x] 明确全部核心条件是否通过；仅完成原型、构建成功或未执行的场景不得算作通过。缺少环境或证据时明确记录未通过关卡，后续实现保持阻塞。
- [ ] 若核心条件失败，携实测证据重新讨论；不得自行新增目录授权、关闭沙盒、恢复父目录配置或降级为子菜单。功能或架构决策变化时同步规格与相关领域文档。
