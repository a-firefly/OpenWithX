# Issue 06：首次配置与本地化

日期：2026-10-23（Asia/Shanghai）。基线：`1dec53093a5c4748095c72008f6ba2362a72c8b0`，用户已确认审查基线与两处测试边界。

## 实现

- 主应用分为 VS Code 检测/选择、原生扩展管理引导、手动 Finder 验证三个步骤。另提供支持范围、日常退出说明及错误恢复入口，长内容可滚动。
- 系统启用、授权同步与用户手动验证分别展示。`FirstRunVerification` 仅保存用户对当前应用路径的确认，不保存项目路径、打开历史或时间。系统启用不会自动确认；仅应用可用、扩展已启用且授权就绪时允许确认。
- 选择/恢复自动发现、路径变化、发现或授权失败、扩展关闭或状态未知、打开错误交接及主动重新验证会撤销确认；同路径重选也撤销。不能检测主应用退出期间发生又恢复的变化，记录是用户确认而非持续健康保证。
- `AppText` 使用 Foundation 的语言代码与推定脚本，取系统首选语言：简体中文显示中文，其他语言使用英文（不会因第二偏好是中文而切换中文）。主界面、Finder 菜单、错误摘要与恢复、选择错误描述均接入。两端声明 en、zh-Hans，无应用内切换。
- 原生 `FIFinderSyncController.showExtensionManagementInterface` 提供入口；补充系统设置 → 通用 → 登录项与扩展路径。实测 macOS 26.7 按类别时 OpenWithX 位于“文件提供程序”，界面据此补充提示。不自动操作 Finder，不增加目录选择、第三方依赖或权限。

## 实机验证

环境 macOS 26.7（25G229）、Apple Silicon、既有用户授权。旧安装备份 `/tmp/OpenWithX-issue06-previous.app`。没有操作 SSD 挂载，没有退出用户原有 VS Code 会话。

1. 安装 Release，应用显示 `/Applications/Visual Studio Code.app` 和扩展已启用，但 Finder 验证为“尚未验证”。主动恢复自动发现后状态为“自动发现（未手动选择）”。无需终端或目录选择完成产品配置（构建部署命令不属于产品流程）。
2. 点击原生扩展管理入口，在系统设置看到“文件提供程序”面板，OpenWithX 开关已开启。完成后返回“登录项与扩展”，确认其属于通用设置中的扩展类别。未修改其他扩展开关。
3. Finder 在 `/private/tmp/OpenWithX-issue05-fixtures` 右击 `Project`，一级菜单为“使用 VS Code 打开”，点击后 VS Code 显示 `Welcome — Project`，Explorer 的 Nested 路径为对应夹具路径。应用仍显示尚未验证；点击确认后才变为用户确认通过，退出再打开后确认保持。
4. 使用 NSOpenPanel 选择 `/Applications/Visual Studio Code.app`，授权已同步，同路径重选撤销旧确认。退出配置应用，从 Finder 再次打开成功；12:12:50 系统记录接受请求，主应用没有进程，后续 VS Code 窗口确认仍为正确 Project。
5. 自建 `/tmp/OpenWithX-issue06-Code.app` 真实正式版副本，通过选择器保存并同步授权。退出主应用后从 Finder 点击，主应用被真实失败唤起，展示指定副本/授权失效与重选指引，原始错误默认折叠，验证按钮禁用。此副本虽已作开发注册，未能作为系统认可的打开副本，因此不记为运行冲突或成功基线，也不将其后改名算作已验证副本失效。
